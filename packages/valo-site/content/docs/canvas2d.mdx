title: Canvas2D compatibility
description: What the drop-in layer covers, how it is verified, and where it deliberately diverges.
---

`valo-web` exposes `ValoCanvasRenderingContext2D`, which takes the calls you
already write.

```ts
import { createValoCanvas } from 'valo-web';

const ctx = await createValoCanvas(document.querySelector('canvas')!);
ctx.fillStyle = 'rgba(200, 255, 61, 0.9)';
ctx.beginPath();
ctx.roundRect(24, 24, 200, 120, [34, 10, 34, 10]);
ctx.fill();
```

## How the claim is checked

The compatibility claim is not a description — it is a test suite. Every scene
is rendered twice, once through valo and once through Chrome's real Canvas2D in
a browser, and the two images are compared pixel by pixel.

```bash
npm run test:conformance
```

At the time of writing that is **105 of 105 scenes passing**, across curated
scenes, degenerate-input scenes, API-shape assertions, query methods, and a
property-based fuzzer that generates command sequences.

Both engines are given the same font bytes rather than each resolving a family
of their own, which is what makes text comparable at all.

## What is covered

State and styles
: `fillStyle`, `strokeStyle`, `globalAlpha`, `globalCompositeOperation`,
`lineWidth`, `lineCap`, `lineJoin`, `miterLimit`, `lineDashOffset`,
`setLineDash`, `getLineDash`, `shadowColor`, `shadowBlur`, `shadowOffsetX/Y`,
`imageSmoothingEnabled`, `imageSmoothingQuality`, `filter`, `save`, `restore`,
`reset`.

Paths and drawing
: `beginPath`, `closePath`, `moveTo`, `lineTo`, `quadraticCurveTo`,
`bezierCurveTo`, `rect`, `roundRect`, `arc`, `ellipse`, `arcTo`, `fill`,
`stroke`, `clip`, `fillRect`, `strokeRect`, `clearRect`, `drawImage`,
`isPointInPath`, `isPointInStroke`, and `Path2D`.

Paint sources
: `createLinearGradient`, `createRadialGradient`, `createConicGradient`,
`createPattern`.

Transforms
: `translate`, `scale`, `rotate`, `transform`, `setTransform`,
`resetTransform`, `getTransform`.

Text
: `font` (the full CSS shorthand), `textAlign`, `textBaseline`, `direction`,
`letterSpacing`, `wordSpacing`, `fontKerning`, `fontStretch`,
`fontVariantCaps`, `textRendering`, `fillText`, `strokeText`, `measureText`
with the full `TextMetrics` box.

Pixels
: `createImageData`, `putImageData`.

CSS filters
: The `filter` string parses the function list — `blur`, `brightness`,
`contrast`, `grayscale`, `hue-rotate`, `invert`, `opacity`, `saturate`,
`sepia`, `drop-shadow` — and applies them in order.

## Deliberate divergences

These are decisions, not gaps. They are listed because a compatibility layer
that hides its edges is worse than one that names them.

<Callout type="warn">
**`getImageData` is not implemented.** It would require a GPU read-back on a
path the rest of the API keeps asynchronous. `putImageData` works.
</Callout>

**Patterns are live.** The specification snapshots the source when you call
`createPattern`; valo re-resolves it at every paint. A canvas mutated after
`createPattern` therefore shows the change, and a not-yet-decoded image yields
a pattern rather than `null`.

**`putImageData` respects the clip.** The specification says it ignores the
clip. valo records draws into a display list, and a draw cannot step outside
the scope it sits in, so under an active clip the write is clipped.

**`hangingBaseline` is approximated** at 0.8 × ascent. valo does not read the
OpenType `BASE` table, so it always takes the fallback Skia uses for fonts
without one.

**Device loss is not observed.** `isContextLost()` answers honestly for the
case it can see — a live context — and does not yet detect a lost device.

## Extensions

The shim also exposes three things valo can do that Canvas2D cannot say:

```ts
ctx.saveLayer(alpha, blendMode);              // an explicitly composited group
ctx.setColorMatrix([/* 20 values */]);        // a 4x5 matrix on later draws
ctx.backdropBlur(x, y, width, height, sigma); // frosted glass over what is drawn
```

For everything else in that category — mask blur styles, gradient spread modes,
difference clips, replayed display lists — reach for [the raw API](/docs/raw-api).

## Frame control

By default mutations are batched and presented once per animation frame. For
explicit control:

```ts
const ctx = await createValoCanvas(canvas, { autoPresent: false });

ctx.beginFrame('#0e0e12');   // discard and start from a clear surface
draw(ctx);
const stats = ctx.present();
```
