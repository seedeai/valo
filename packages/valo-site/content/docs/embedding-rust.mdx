---
title: Embedding from Rust
description: Hand valo a wgpu device and a render target. It never owns a window, a surface loop, or a font source.
---

```bash
cargo add valo
```

valo is host-agnostic on purpose. It takes bytes, handles and display lists, and
it never reaches for a font file, a network, or an application model. Fonts
arrive registered, images arrive uploaded, and the frame target arrives from you.

## A frame

```rust
use valo::{Color, Context, DisplayListBuilder, Paint, Rect, RenderTarget};

let mut context = Context::new(device, queue);

let mut builder = DisplayListBuilder::new();
builder.draw_rect(
    Rect::new(10.0, 10.0, 100.0, 80.0),
    &Paint::from_color(Color::rgb(0.9, 0.3, 0.2)),
);
let list = builder.build();

let stats = context.render(&list, &RenderTarget {
    view,
    texture,
    format: wgpu::TextureFormat::Rgba8Unorm,
    size: [800, 600],
    clear: Some(Color::WHITE),
});
```

`Context` owns the wgpu device and every shared cache. `DisplayListBuilder`
owns none of it — recording is GPU-free, needs no thread affinity, and produces
an `Arc<DisplayList>` you can replay whenever you like.

## Where things live

| Crate | Role |
| --- | --- |
| `valo-geometry` | Points, rects, paths, 4×4 matrices, strokes, colour. No GPU, no unicode |
| `valo-dl` | Recording: builder, ops, paints, shaders. GPU-free and `Send + Sync` |
| `valo-text` | Shaping, bidi, wrapping, glyph raster, SDF, COLR. GPU-free |
| `valo-renderer` | The wgpu core: planner, encoder, pipelines, atlases, pools, caches |
| `valo` | The facade hosts use, plus `Hud` |
| `valo-svg` | SVG to display list |
| `valo-system-fonts` | Native OS font discovery behind `FontSource` |
| `valo-capi` | The C ABI, for non-Rust embedders |

Depending on `valo` gets you the facade and re-exports of everything above it.

## Surfaces

`Surface` wraps a swapchain; `Offscreen` renders to a texture you keep;
`PersistentCanvas` keeps a canvas's pixels between frames, which is what
Canvas2D's "what you drew stays drawn" needs.

```rust
let mut surface = Surface::new(&instance, &adapter, context.device(), target, size)?;
if let Some(frame) = surface.acquire() {
    context.render(&list, &frame.target(Some(Color::BLACK)));
    context.present(frame);
}
```

Present and read-back belong to you. valo will not run a loop on your behalf.

## Text

```rust
use valo::{FontCollection, ParagraphBuilder, ParagraphStyle, TextStyle};

let mut fonts = FontCollection::new();
let id = fonts.register("Inter", bytes).expect("a usable face");
fonts.add_fallback(id);

let mut builder = ParagraphBuilder::new(&mut fonts);
builder.style(ParagraphStyle::default()).add_text("Hello", &TextStyle::default());
let mut paragraph = builder.build();
paragraph.layout(520.0);
```

For native applications that want the operating system's fonts,
`valo-system-fonts` implements `FontSource`. It is never a WebAssembly
dependency.

## From C

The committed header is `crates/valo-capi/include/valo.h`. Every object is an
opaque handle from a `valo_*_new` call, released by the matching
`valo_*_dispose`; handles are not thread-safe.

```c
ValoContext *context = valo_context_new();
ValoDisplayListBuilder *builder = valo_builder_new();
valo_builder_draw_rect(builder, 10, 10, 100, 80, paint);
ValoDisplayList *list = valo_builder_build(builder);
valo_context_render(context, list, /* target */ ...);
valo_display_list_dispose(list);
valo_builder_dispose(builder);
```

On macOS the context can attach directly to a `CAMetalLayer` and render into a
drawable's texture.

## Testing what you draw

Golden pixel tests run on a headless native device — no browser, no display
server:

```sh
cargo test                 # unit + golden pixel tests
VALO_BLESS=1 cargo test    # accept new goldens after an intended visual change
```

Goldens compare within ±3 per channel. A golden that changes because you changed
*what* the scene draws is fine. A golden that changes because you changed *how*
it draws wants an explanation first.
